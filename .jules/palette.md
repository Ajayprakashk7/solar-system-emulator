## 2024-03-20 - Missing Aria Hidden on Decorative Icons with Hidden Text
**Learning:** Using Tailwind's responsive hiding classes (`hidden sm:inline`) on descriptive text elements means that on smaller screens (mobile), the text is completely removed from the DOM/accessibility tree. If the remaining visible element is just a decorative icon (e.g., `←`, `✕`, `🎯`) without `aria-hidden="true"`, and the parent button relies on the hidden text for its accessible name, screen readers will either read nothing or attempt to read the non-semantic icon character itself, resulting in a confusing experience.
**Action:** When hiding text alongside an icon responsively, always apply `aria-hidden="true"` to the decorative icon, and ensure the parent button has an explicit, persistent `aria-label` that provides the accessible name regardless of viewport size. Never rely on conditionally visible text for the primary accessible name if it can be hidden.
