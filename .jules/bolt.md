## 2025-01-20 - Asteroid Belt Animation Optimization
**Learning:** The previous implementation animated the asteroid belt via the CPU in a `useFrame` loop. It recalculated transformation matrices (e.g. `setMatrixAt`) for each of the 500-1000 instanced asteroids every few frames, which induced high O(N) overhead per loop and significant memory bandwidth usage for uploading buffer data to the GPU. This compromises the 60 FPS constraint on low-end mobile devices.
**Action:** I've applied a GPU-based solution using `onBeforeCompile` to inject a custom vertex shader into the `meshStandardMaterial`. This offloads matrix calculations to the GPU. Now, each asteroid's local rotation is performed entirely within the vertex shader based on its instanced `aRotationSpeed` attribute and a `uTime` uniform. This achieves O(1) CPU time complexity per frame and eliminates constant instanced matrix recalculations, fulfilling the 'No Drop' constraint.
