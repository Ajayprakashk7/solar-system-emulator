## 2024-03-24 - Performance and Cleanup Optimizations
**Learning:** Three.js orbit controls managed by `@react-three/drei` should not have `dispose()` called explicitly in cleanup functions. Calling `dispose()` manually interferes with R3F's management. When applying `frustumCulled={true}` to instance meshes and custom geometries, you must explicitly call `computeBoundingSphere()`. Furthermore, overwriting `gl.dispose` in React Three Fiber must retain a call to the original `gl.dispose` to prevent memory leaks from undestroyed canvases. Finally, limit check instances for rate-limiting using `lib/rate-limiter.ts` should pass a uniquely identifying IP string (from headers like `x-forwarded-for` or `x-real-ip`) instead of relying on the global default bucket.
**Action:** Removed explicit `controls.dispose()` in `CameraController.js`. Enabled `frustumCulled={true}` for `AsteroidBelt.js` and `CosmicDust.js` meshes, and calculated bounds properly using `computeBoundingSphere()`. Retained the original `gl.dispose()` behavior in `SolarSystem.js`. Fixed IP rate limits in `app/api/nasa/moon/[name]/route.ts` and `app/api/nasa/planet/[name]/route.ts`.
