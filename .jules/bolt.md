## 2024-05-15 - Array Allocations in useFrame Cause Garbage Collection Micro-Stutters
**Learning:** Passing inline arrays (e.g., `[x, y, z]`) to context functions or state updates inside R3F's `useFrame` loop forces the JavaScript engine to allocate new memory every single frame per object. In a solar system with 8 planets running at 60 FPS, this translates to 480 array allocations per second, which quickly fills the heap and causes the garbage collector to pause execution, creating noticeable micro-stutters.
**Action:** Always refactor high-frequency context update functions (like `updatePlanetPosition`) to accept individual scalar arguments `(x, y, z)` instead of array objects. In the receiver function, mutate an existing pre-allocated array or `Vector3` in-place rather than overwriting it with a new array reference.
