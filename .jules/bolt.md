## 2024-05-24 - Three.js Frustum Culling and Controls Disposal Lifecycle
**Learning:** Frustum culling for instanced meshes or buffer geometries relies entirely on accurately calculated bounding spheres. By default, standard Three.js implementations require manual invocation (e.g., `computeBoundingSphere()`) if vertex positions are initialized procedurally, otherwise `frustumCulled={false}` acts as an unoptimized bypass. Furthermore, manually calling `.dispose()` on camera controllers provided by React Three Fiber wrappers (like `DreiOrbitControls`) conflicts with internal unmount lifecycles resulting in orphaned events.
**Action:** Always compute bounding spheres natively on `InstancedMesh` references or `BufferGeometry` instead of bypassing culling. Never explicitly dispose Drei components inside standard React cleanup blocks unless detached from the R3F graph context.
