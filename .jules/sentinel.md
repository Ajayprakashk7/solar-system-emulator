## 2023-10-27 - Missing Rate Limiting & Invalid Header Formats
**Vulnerability:** The APOD and NEO API routes were completely lacking rate limiting, exposing the application to potential API quota exhaustion and DoS from excessive NASA API calls. Furthermore, existing rate limit implementations in the Moon and Planet routes outputted 'X-RateLimit-Reset' as an ISO date string instead of a valid Unix timestamp, which violates HTTP header specifications and could cause parsing errors on clients.
**Learning:** All endpoints that interact with third-party rate-limited APIs (like NASA) must consistently employ rate limiting. Additionally, HTTP headers require strictly formatted values, where date headers for resets should typically be Unix timestamps or HTTP dates, not raw ISO 8601 strings.
**Prevention:** Always ensure new API routes wrap external calls in the shared `nasaRateLimiter`. When outputting Date objects to HTTP headers, ensure they are converted correctly (e.g., `Math.floor(date.getTime() / 1000)`).
