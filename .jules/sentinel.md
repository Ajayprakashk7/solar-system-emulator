## 2024-05-15 - Unsafe Rate Limiting IP Extraction
**Vulnerability:** Indiscriminately selecting the left-most IP in `x-forwarded-for` for rate limiting.
**Learning:** This is vulnerable to IP spoofing. An attacker can trivially send a request with a fake `X-Forwarded-For: fake-ip, real-ip` header. If the left-most IP is selected and no trusted proxy list is configured, the rate limit can be bypassed by randomizing the fake IP, or conversely, a denial of service can be caused against another client by impersonating their IP.
**Prevention:** If no specific trusted proxy setup is available, avoid parsing `x-forwarded-for` manually. Instead, it is safer to rely on `x-real-ip` when provided by the reverse proxy, or fallback to an identifier that isn't trivially spoofed to bypass limits. However, in this case, removing `x-forwarded-for` altogether might break rate-limiting for clients behind legitimate proxies if `x-real-ip` isn't set. If you must use `x-forwarded-for`, parse from right-to-left bypassing known trusted proxies. If no trusted proxies are known, taking the right-most IP is marginally safer as it's the last intermediate proxy (often a CDN node), but this groups all traffic from that node together, potentially causing a localized DoS. A better approach when no trusted proxies are defined is to stick with `x-real-ip` if available, otherwise just use a fallback identifier.
