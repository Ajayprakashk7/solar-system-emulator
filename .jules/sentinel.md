## 2024-05-24 - API Quota Exhaustion via Improper Limiter Logic
**Vulnerability:** External API proxy endpoints (like `app/api/nasa/planet/[name]/route.ts`) relied on a shared global rate limiter. By evaluating this global limit without IP-based protection, malicious actors could easily exhaust the shared quota and cause a DoS for all users.
**Learning:** When implementing rate limiting to protect external shared quotas, you must implement multiple tiers (per-IP and global). Furthermore, you must evaluate the strict, user-specific limits *first* using inline short-circuit logic (e.g., `if (!ipRateLimiter.check(ip).success || !nasaRateLimiter.check().success)`). Pre-evaluating limits executes both checks, defeating the short-circuit and needlessly depleting shared quotas.
**Prevention:** Always implement IP-based rate limiting alongside global limits, and strictly use inline short-circuit boolean logic to prevent execution of global checks when the IP limit is already exceeded.
