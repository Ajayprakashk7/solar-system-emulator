## 2024-05-14 - Missing Rate Limiting on External API Proxy Endpoints
**Vulnerability:** `app/api/nasa/apod/route.ts` and `app/api/nasa/neo/route.ts` lack any form of rate limiting, and `app/api/nasa/moon/[name]/route.ts` and `app/api/nasa/planet/[name]/route.ts` only use a global rate limiter. This allows malicious actors to exhaust the global NASA API quota (1000 requests/hour) by flooding these unauthenticated endpoints, causing a Denial of Service (DoS) for all legitimate users. Furthermore, since the global limit applies to the whole server instead of per IP, a single user could accidentally or intentionally consume the entire quota.
**Learning:** Proxying authenticated external APIs on public endpoints requires both a global limit (to protect the upstream quota) and a per-IP limit (to ensure fair use and prevent DoS by individual IPs). Specifically, the per-IP limiter must be evaluated *before* the global limiter to prevent an attacker from exhausting the global limit.
**Prevention:** Implement an IP-based rate limiter alongside the global one. Check the IP limit first using `x-real-ip` (fallback to `x-forwarded-for`), short-circuit if exceeded, and then check the global limit. Ensure both limiters are applied consistently across all proxy endpoints.
