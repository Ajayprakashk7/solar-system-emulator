## 2024-05-24 - Rate Limiting Global Scope Vulnerability
**Vulnerability:** The `nasaRateLimiter.check()` method defaults to a 'global' identifier if no argument is passed. This means all incoming requests from all users share the same rate-limiting bucket. This is a severe Denial of Service (DoS) risk, as a single abusive IP or user could exhaust the 900 requests/hour limit, denying service to all other legitimate users.
**Learning:** Default arguments in rate limiter classes (like `identifier: string = 'global'`) can obscure the fact that limits are applied system-wide rather than per-user, especially when the caller (e.g., API route handlers) fails to explicitly pass a unique identifier (like the client IP).
**Prevention:** Rate limiting middleware or functions should explicitly require a unique client identifier (e.g., IP address, user ID, session token) and should never default to a global bucket for application endpoints, unless specifically intending to throttle absolute global traffic regardless of the source. Extract the real client IP using `request.headers.get('x-real-ip')` or `request.headers.get('x-forwarded-for')`.
