## 2024-05-24 - Rate Limiting Client IP Identification and Header Validation
**Vulnerability:** A DoS risk existed because `nasaRateLimiter.check()` was called without an identifier. This defaulted to a global rate limit bucket across all users. Also, rate limit response headers exposed the raw `Date.toISOString()` instead of expected Unix timestamps, violating standard practices.
**Learning:** In Next.js 15, `request.ip` is removed. Real client IP must be carefully extracted from HTTP headers. Using the left-most value from `x-forwarded-for` or using `x-real-ip` is crucial to prevent spoofing and properly identifying individual clients behind proxies. The `reset` value from our RateLimiter is a JS Date object, and must be explicitly converted to epoch timestamp using `Math.floor(date.getTime() / 1000)`.
**Prevention:** Always extract the client IP securely using headers when `request.ip` is unavailable. Always explicitly pass the identified client IP to the rate limiter's check method. Convert Date objects representing rate limit resets to Unix timestamps before passing them in HTTP headers.
