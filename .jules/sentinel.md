## 2024-05-18 - [Add rate limiter scoped to client IP]\n**Vulnerability:** Global rate limiter causes denial of service vulnerability.\n**Learning:** The previous implementation used a global rate limiter without scoping the limiter to a specific client. This meant an attacker could easily lock out all legitimate users by exhausting the rate limit.\n**Prevention:** In Next.js, use a client-specific identifier like `request.headers.get('x-forwarded-for')` when checking the rate limit instead of a global limit. Additionally, make sure you correctly include the required rate-limit headers in the API responses when building APIs.
