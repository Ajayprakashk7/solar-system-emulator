## 2024-05-18 - Missing Content Security Policy (CSP)
**Vulnerability:** The application lacks a Content-Security-Policy (CSP) header, leaving it vulnerable to XSS attacks, data injection, and unauthorized resource loading.
**Learning:** Adding a CSP header is a critical defense-in-depth security enhancement. The memory instructions strictly note: "When defining a Content-Security-Policy (CSP) header, discovering a package dependency (e.g., @vercel/analytics in package.json) does not justify hallucinating its corresponding external domains (e.g., va.vercel-scripts.com) for the whitelist. You must exclusively use domains that are explicitly discovered and verified within the codebase." Thus, our CSP should only whitelist explicitly discovered domains like `images-assets.nasa.gov`, `api.nasa.gov`, and `mars.nasa.gov`, which are verified in `next.config.mjs`'s `remotePatterns`.
**Prevention:** Implement a strict CSP in `next.config.mjs` and include it in the global `securityHeaders`.
